### 3.2 E동 식별 (사용자 확인 완료, 2026-11-16)

대표 사진(`thumb.jpg`): **왼쪽 포스코ICT, 가운데 E동, 오른쪽 F동** (사용자 확인).

방향 검증 (OSM 위경도, E동 중심 기준):

| 대상 | 방위 | 거리 |
|---|---|---|
| F동 | 305° (북서) | 약 65 m |
| 포스코ICT | 143° (남동) | 약 75 m |
| 우주공원 | 249° (서남서) | 약 97 m |

- 포스코가 왼쪽, F동이 오른쪽으로 보이려면 **북동쪽에서 남서쪽을 바라봐야** 한다. 사진 앞쪽의 지하화된 대왕판교로와 빨간 금토천 자전거도로도 북동쪽 지형과 맞다.
- 따라서 사진 속 면 = **E동·F동 `+z` 면 (대왕판교로 쪽, 방위 35°)**. 우주공원은 건물 반대편(`-z` 면 쪽)에 있다.
- 주의: 현재 시작 시점(`efec680`, 우주공원에서 바라봄)에서는 `-z` 면이 보인다. 사진으로 확인된 특징(둥근 프레임, 유리 박스, 색 띠, 간판)은 `+z` 면에 넣는다.
  `-z` 면 외관은 아직 자료가 없다(로드뷰 확인 지점 2·6). 시작 시점에서도 확인된 외관을 보여주려면 `+z` 쪽 시점을 추가하거나, `-z` 면은 확인될 때까지 같은 언어로 단순화한다.

### 3.4 게임에 우선 반영할 특징 (효과 큰 순)

1. **둥근 모서리 은색 프레임**: 이 단지에서 가장 눈에 띄는 특징. `+z`/`-z` 면 테두리에 파괴 가능한 프레임 블록을 추가하거나 기존 테두리 블록 재질을 은색으로 바꾼다.
2. **돌출 유리 박스 + 색 띠**: 파괴했을 때도 눈에 띄는 요소. 박스는 파괴 블록으로 만들고 색 띠는 얇은 블록.
3. **끝 면의 은색 패널 + 원형 창**: `±x` 면 재질을 유리에서 금속 패널로 바꾸고 원형 창은 텍스처로 그린다.
4. **간판 위치**: 중앙 → `+z` 면 상단 오른쪽.
5. 기단부 로비(1층 유리), 옥상 설비.

## 5. Codex 구현 가이드

### 5.1 데이터 구조 제안

`dist/model.js`의 각 건물에 `exterior` 설정을 추가한다. 관찰 기록이 없는 항목은 지금의 절차적 기본값을 쓴다.

```js
exterior: {
  verified: false,                  // 사진/로드뷰로 대조한 면이 있으면 true, 아래 sources 필수
  sources: ['카카오 로드뷰 2024-05 (관찰 기록, 이미지 미사용)'],
  groundFloorScale: 1.0,            // 1층 높이 배율
  faces: {
    '+z': { type: 'curtainWall', glass: '#4d7f8f', frame: '#c9d3d6', band: true, finEvery: 2, entrance: true },
    '-z': { ... }, '+x': { ... }, '-x': { ... },
  },
  roof: { parapet: 0.6, equipment: [{ x: -0.3, z: 0, w: 4, d: 3, h: 2 }] }, // 위치는 건물 크기 대비 비율
  sign: { text: 'INNOVALLEY / E', face: '+z', anchor: 'top-center' },
}
```

### 5.2 연결 지점

- 파괴 블록 생성: `dist/building.js` `buildTarget()`. 면 방향별 재질·패턴을 `exterior.faces[face]`에서 읽게 한다.
  블록 수와 크기는 바꾸지 않는다(파괴율·붕괴 판정 유지). 바꿀 경우 테스트 기준을 함께 갱신한다.
- 유리·외벽 재질: `dist/architecture.js` `glassMaterial()` 등. 면 설정의 색과 띠 여부를 인자로 받게 한다.
  재질은 색·패턴 조합별로 캐시해서 공유한다(GPU 리소스 누적 금지 규칙).
- 간판: `createSignMaterial()`에 문구, `buildTarget()`에 면과 위치를 넘긴다.
- UI 문구: 외관이 대조된 면이 생기면 `index.html` 모델 정보 창에 "어떤 면을 어떤 자료로 대조했는지"를 쓴다.
  대조하지 않은 부분은 계속 "단순화"로 표시한다.

### 5.3 완료 기준

1. 관찰 기록이 없으면 지금 화면과 같다(기본값 회귀 없음).
2. 관찰 기록의 값이 해당 면에만 반영된다. 블록 수, 파괴율 계산, 무기 판정 테스트 통과.
3. 외부 이미지 파일을 추가하지 않는다(직접 촬영 사진 제외). 상용 지도 이미지 픽셀을 텍스처로 쓰지 않는다.
4. 브라우저 스크린샷으로 확인 지점 1~7, 그리고 3.2절 대표 사진과 같은 방향에서 본 게임 화면을 남겨 관찰 기록과 나란히 비교한다.
   `view.js`의 카메라를 2절의 바라볼 방향으로 맞추면 된다(게임 `+z`는 실제 방위 35°).
