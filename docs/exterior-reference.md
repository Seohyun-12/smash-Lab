# E·F동 외관 보완 참고 자료

HANDOFF.md 후속 작업 3번(각 면 외관 대조)과 4번(항공/위성/거리영상 사용 조건)을 진행하기 위한 자료다.
작성: Claude Code, 2026-11-16. 기준 데이터: `dist/site.js` (OSM way 684716463 E동, 684716461 F동).

## 3. 관찰 기록 양식

사용자(또는 사진을 받은 도구)가 채운다. 모르는 칸은 비워 둔다. 빈 칸은 현재 절차적 값을 유지한다.
촬영 연도가 표시되면 함께 적는다(외관이 바뀌었을 수 있음).

```yaml
# docs/exterior-observations.yaml 로 저장해도 된다.
source: ""            # 예: 카카오 로드뷰 2024-05, 직접 촬영 2026-11
E:
  totalFloorsVisible: # 지상 층수 (OSM 값: 10)
  groundFloor:
    taller: null      # 1층이 다른 층보다 높은가 (true/false), 대략 몇 배
    lobbyFaces: []    # 출입구가 있는 면: +z / -z / +x / -x
    material: ""      # 예: 짙은 유리, 석재, 필로티
  facade:             # 면마다 다르면 +z, -z 등으로 나눠 적는다
    type: ""          # 커튼월(전면 유리) / 띠창(유리+수평 띠) / 격자 창 / 혼합
    glassColor: ""    # 예: 청록, 짙은 남색, 은색 반사
    frameColor: ""    # 멀리언·띠 색
    bandEveryFloor: null   # 층마다 불투명 수평 띠가 있는가
    verticalFinsEvery: ""  # 세로 핀/멀리언 간격 (창 몇 칸마다, 또는 m)
    accentPanels: ""  # 색 패널·코너 처리 등 특징
  roof:
    parapetHeight: "" # 낮음 / 1층 높이 정도 / 높음
    equipment: ""     # 냉각탑·기계실 박스 위치(어느 끝), 개수
    crown: ""         # 상부 장식·옥탑 형태
  sign:
    text: ""          # 실제 간판 문구
    face: ""          # +z / -z / +x / -x
    position: ""      # 상단 중앙, 모서리, 1층 캐노피 등
  podium: ""          # 저층부 돌출·캐노피·연결 통로
F:
  # E와 같은 항목. 다른 것만 적는다.
connection: ""        # E-F 사이 연결 다리·지붕·저층 연결 여부
```

## 4. Codex 구현 가이드

### 4.1 데이터 구조 제안

`dist/model.js`의 각 건물에 `exterior` 설정을 추가한다. 관찰 기록이 없는 항목은 지금의 절차적 기본값을 쓴다.

```js
exterior: {
  verified: false,                  // 사진/로드뷰로 대조한 면이 있으면 true, 아래 sources 필수
  sources: ['카카오 로드뷰 2024-05 (관찰 기록, 이미지 미사용)'],
  groundFloorScale: 1.0,            // 1층 높이 배율
  faces: {
    '+z': { type: 'curtainWall', glass: '#4d7f8f', frame: '#c9d3d6', band: true, finEvery: 2, entrance: true },
    '-z': { ... }, '+x': { ... }, '-x': { ... },
  },
  roof: { parapet: 0.6, equipment: [{ x: -0.3, z: 0, w: 4, d: 3, h: 2 }] }, // 위치는 건물 크기 대비 비율
  sign: { text: 'INNOVALLEY / E', face: '+z', anchor: 'top-center' },
}
```

### 4.2 연결 지점

- 파괴 블록 생성: `dist/building.js` `buildTarget()`. 면 방향별 재질·패턴을 `exterior.faces[face]`에서 읽게 한다.
  블록 수와 크기는 바꾸지 않는다(파괴율·붕괴 판정 유지). 바꿀 경우 테스트 기준을 함께 갱신한다.
- 유리·외벽 재질: `dist/architecture.js` `glassMaterial()` 등. 면 설정의 색과 띠 여부를 인자로 받게 한다.
  재질은 색·패턴 조합별로 캐시해서 공유한다(GPU 리소스 누적 금지 규칙).
- 간판: `createSignMaterial()`에 문구, `buildTarget()`에 면과 위치를 넘긴다.
- UI 문구: 외관이 대조된 면이 생기면 `index.html` 모델 정보 창에 "어떤 면을 어떤 자료로 대조했는지"를 쓴다.
  대조하지 않은 부분은 계속 "단순화"로 표시한다.

### 4.3 완료 기준

1. 관찰 기록이 없으면 지금 화면과 같다(기본값 회귀 없음).
2. 관찰 기록의 값이 해당 면에만 반영된다. 블록 수, 파괴율 계산, 무기 판정 테스트 통과.
3. 외부 이미지 파일을 추가하지 않는다(직접 촬영 사진 제외). 상용 지도 이미지 픽셀을 텍스처로 쓰지 않는다.
4. 브라우저 스크린샷으로 확인 지점 1~7과 같은 방향에서 본 게임 화면을 남겨 관찰 기록과 나란히 비교한다.
   `view.js`의 카메라를 2절의 바라볼 방향으로 맞추면 된다(게임 `+z`는 실제 방위 35°).

### 4.4 항공/위성/거리영상 API 연동 (별도 기능, 선택)

게임 안에 실제 영상을 띄우려면 제공자 API를 정식으로 써야 한다. 이번 범위에서는 하지 않는다.

- V-World: 인증키 발급(무료), 공공누리 유형과 출처 표기 확인. WMTS 항공영상을 바닥 텍스처로 쓰는 방안을 검토할 수 있다.
- Mapillary: 토큰 필요, CC BY-SA. 해당 지점 사진이 있는지 먼저 확인한다.
- 키는 코드·Git에 넣지 않는다(AGENTS.md). 정적 호스팅에서는 키가 노출되므로 도메인 제한 키만 쓴다.
